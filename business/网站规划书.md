# 实时商业与AI信息网站 — 完整规划书

> **项目目标**：搭建一个实时聚合、展示商业资讯与AI领域动态的信息网站，支持多数据源实时更新、智能分类、个性化订阅。

## 二、技术栈选型

### 2.1 前端

| 技术 | 选型 | 理由 |
|------|------|------|
| **框架** | Next.js 14+ (App Router) | SSR/SSG/ISR 全支持，SEO 友好，内置 API Routes |
| **语言** | TypeScript | 类型安全，减少运行时错误 |
| **样式** | Tailwind CSS + shadcn/ui | 快速构建 UI，统一设计系统 |
| **状态管理** | React Query (TanStack Query) | 缓存、自动重取、实时刷新 |
| **实时通信** | EventSource (SSE) + WebSocket | SSE 用于单向推送，WS 用于双向交互 |
| **图表** | Recharts / Chart.js | 数据可视化 |
| **测试** | Vitest + Playwright | 单元测试 + E2E 测试 |

### 2.2 后端

| 技术 | 选型 | 理由 |
|------|------|------|
| **运行时** | Node.js (Next.js API Routes) + Python (FastAPI 可选) | 统一前端后端语言，Python 用于 AI/NLP 任务 |
| **API 框架** | Next.js API Routes + tRPC (可选) | 类型安全的 API 调用 |
| **任务队列** | BullMQ (Redis) | 定时抓取、异步任务 |
| **认证** | NextAuth.js | 支持 OAuth (Google/GitHub) |
| **数据库 ORM** | Prisma | 类型安全，迁移方便 |

### 2.3 数据与存储

| 技术 | 用途 | 说明 |
|------|------|------|
| **PostgreSQL** | 主数据库 | 存储用户、文章、分类等结构化数据 |
| **Redis** | 缓存 + 实时队列 | 热点数据缓存，WebSocket 广播，任务队列 |
| **Elasticsearch** | 全文搜索 | 文章内容搜索、关键词高亮 |
| **S3 / MinIO** | 对象存储 | 图片、静态资源 |

### 2.4 DevOps

| 技术 | 用途 |
|------|------|
| **Docker** | 容器化部署 |
| **Vercel / Railway** | 前端 + API 部署 |
| **GitHub Actions** | CI/CD 自动化 |
| **Prometheus + Grafana** | 监控与报警 |

## 四、数据模型设计

```prisma
// 核心数据模型

model Article {
  id          String   @id @default(cuid())
  title       String
  url         String   @unique
  source      String   // 数据源名称
  category    String   // business / ai / technology
  summary     String?  // AI 生成的摘要
  content     String?  // 完整内容（可选）
  imageUrl    String?
  publishedAt DateTime
  fetchedAt   DateTime @default(now())
  sentiment   Float?   // 情感分数 -1 ~ 1
  tags        String[] // 关键词标签
  viewCount   Int      @default(0)
  
  // 索引
  @@index([category, publishedAt])
  @@index([source])
  @@index([publishedAt])
}

model User {
  id            String   @id @default(cuid())
  email         String?  @unique
  name          String?
  image         String?
  preferences   Json?    // 偏好设置 JSON
  bookmarks     Bookmark[]
  subscriptions Subscription[]
  createdAt     DateTime @default(now())
}

model Bookmark {
  id        String  @id @default(cuid())
  userId    String
  articleId String
  user      User    @relation(fields: [userId], references: [id])
  article   Article @relation(fields: [articleId], references: [id])
  createdAt DateTime @default(now())
  
  @@unique([userId, articleId])
}

model Subscription {
  id        String  @id @default(cuid())
  userId    String
  keyword   String  // 订阅关键词
  category  String? // 订阅分类
  user      User    @relation(fields: [userId], references: [id])
  createdAt DateTime @default(now())
}

model Source {
  id        String   @id @default(cuid())
  name      String   @unique
  baseUrl   String?
  status    String   @default("active") // active / error / paused
  lastFetch DateTime?
  errorMsg  String?
}
```

## 五、实时更新机制

### 5.1 数据采集流水线

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 定时任务  │───▶│ 数据抓取  │───▶│ 清洗分类  │───▶│ 入库存储  │
│ (Cron)   │    │ (API)    │    │ (AI)     │    │ (DB)     │
└──────────┘    └──────────┘    └──────────┘    └────┬─────┘
                                                      │
                                                      ▼
                                              ┌──────────────┐
                                              │  Redis Pub   │
                                              │  / Sub 广播  │
                                              └──────┬───────┘
                                                      │
                                              ┌────────▼───────┐
                                              │  WebSocket /   │
                                              │  SSE 推送给    │
                                              │  客户端        │
                                              └────────────────┘
```

### 5.2 更新策略

| 策略 | 说明 | 间隔 |
|------|------|------|
| **轮询抓取** | 定时调用外部 API 拉取最新内容 | 每 5-15 分钟 |
| **Webhook 接收** | 部分平台支持推送通知 | 即时 |
| **SSE 推送** | 服务端有新内容立即推送给前端 | 即时 |
| **前端轮询回退** | 若 SSE 断开，降级为定期轮询 | 每 30 秒 |

## 十、风险与应对

| 风险 | 影响 | 应对方案 |
|------|------|---------|
| 外部 API 限流/下线 | 数据源中断 | 多源冗余，本地缓存，降级提示 |
| 实时推送高并发 | 服务器压力大 | Redis 广播，连接池管理，限流 |
| AI 摘要成本 | 运营成本增加 | 仅对热门文章生成摘要，缓存结果 |
| 数据版权问题 | 法律风险 | 仅展示摘要+原文链接，不存储全文 |
| 内容质量参差 | 用户体验下降 | AI 内容过滤，评分机制，用户举报 |
